# acoes

O que é: as quatro Ações que o chatbot pode executar, cada uma numa tool do LangChain (`tools.py`): `consultar_pedido` lê a tabela seed de Pedidos do Cliente atual; `consultar_base_de_conhecimento` chama o mesmo retriever do caminho de dúvida; `emitir_reembolso` passa pelo Gate de Aprovação (`reembolso.py`), onde valor acima do limite ou Reembolso recente forçam aprovação por código e, abaixo disso, o Jev devolve a probabilidade de a operação ser crítica; `abrir_ticket` usa o trabalhador para gerar resumo, categoria e prioridade (`ticket.py`). Por que assim: a única Ação com efeito irreversível é o Reembolso, e é a única que chama `interrupt`, congelando a Conversa como Aprovação Pendente até um Atendente decidir; toda Ação é anunciada no stream como `tool_call` para o chat mostrar o que está acontecendo. Teoria em um parágrafo: tool calling é o modelo escolher, por nome e argumentos tipados, uma função que o código executa; o modelo nunca executa nada, só pede, e por isso o lugar certo para regras de negócio e para pedir aprovação humana é dentro da função, não no prompt.
