# api

Contrato REST mínimo em FastAPI, sem lógica de domínio: o Cliente (identificado pelo header `X-Cliente-Id`, ou pela query `cliente_id` no stream, porque o EventSource do navegador não envia headers; sem autenticação de verdade, que está fora do escopo) cria e lista Conversas, envia mensagens com `message_id` e recebe 202 mesmo quando repete o envio, lista as mensagens e abre o stream SSE da Conversa; o Atendente, protegido pelo header `X-Atendente-Token` comparado com `config.atendente_token`, lista Aprovações Pendentes, aprova ou rejeita com motivo (cada decisão vira um job de retomada na fila), lista Tickets, lê a Conversa de um Ticket e lê ou edita a Memória Procedural de um Cliente. O SSE (`GET /conversas/{id}/stream`) faz `LISTEN` no canal da Conversa antes de responder e repassa cinco eventos, com `event` igual ao tipo e `data` igual ao JSON dos dados: `token` (`texto`), `tool_call` (`nome`, `args`), `approval_required` (`pedido_id`, `valor`, `probabilidade`, `resumo`, `aprovacao_id`), `message_done` (`mensagem_id`, `conteudo`) e `error` (`mensagem`). Ao conectar, se já existe uma mensagem do assistente gravada, o stream começa reenviando-a como `message_done` com `reenvio: true`, e é assim que o front se recupera de uma queda de conexão sem perder a resposta. Cada request abre a própria conexão com o Postgres e a fecha ao terminar; `/health` só diz se Postgres e Qdrant respondem.
