# Backend organizado por conceito de domínio, não por camada

Cada pasta do backend corresponde a um termo do glossário (grafo, rag, memoria, guardrails, roteador, acoes, loja, conversas, fila, api, observabilidade, evals) e tem um README de um parágrafo. A organização por camada (routers, services, repositories) foi rejeitada porque espalha cada conceito em três lugares e prejudica o objetivo didático do projeto. Regras de acoplamento: o grafo importa das outras pastas, e nenhuma outra pasta importa do grafo; quem entrega o grafo à fila, à API e aos evals é a raiz de composição (`ampere/composicao.py`, usada por `ampere/cli.py`). As pastas `prompts/` e `regras/` são conteúdo, não lógica: qualquer conceito lê delas, e elas não importam de ninguém. `nucleo/` é a infraestrutura compartilhada (configuração, modelos, Jev, banco). As regras são verificadas por `backend/tests/unit/test_arquitetura.py`, que lê os imports de cada arquivo.
