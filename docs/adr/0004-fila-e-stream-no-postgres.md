# Fila, idempotência e stream de tokens no Postgres

A API recebe mensagens com um message_id gerado no cliente, grava a mensagem e o job numa tabela de fila com chave única (idempotência), na mesma transação que um `NOTIFY fila_de_jobs`, e responde 202. Um worker separado dorme em `LISTEN fila_de_jobs`, acorda com o aviso (ou por um intervalo de segurança), consome com SELECT FOR UPDATE SKIP LOCKED e executa o grafo. Os eventos viajam do worker para a API por LISTEN/NOTIFY num canal por Conversa, e a API repassa por SSE com seis eventos: token, tool_call, etapa, approval_required, message_done e error. A resposta final é gravada antes do aviso, para permitir recuperação após reconexão. Redis (Celery, arq, Pub/Sub) foi rejeitado para não adicionar um terceiro serviço no Railway, polling puro foi rejeitado por abrir consultas à toa e atrasar a resposta, e executar o grafo dentro da API foi rejeitado porque tornaria a fila decorativa.
